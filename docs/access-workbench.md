# 接入工作台

这次改动把开放接入、接入体检与配置保护、线路和账单整合为一个无需登录的工作台。已有用户仍会回到上次页面；新安装默认打开工作台。

## 开放接入

- 配置中心“添加供应商”默认打开通用表单，支持原有官方预设和自定义服务。
- HRouter 快捷接入作为独立选项保留，继续识别 Key、模型映射与用量。
- 工作台可选择 CC Switch 的 `cc-switch.db`，先预览再导入所选条目。数据库只读打开，目标条目采用 `cc-import-` 前缀，已存在条目跳过。
- 导入不会激活供应商、改写客户端配置或修改源数据库。官方登录态、托管 OAuth、OMO 配置和用量脚本不迁移；需要在对应入口重新配置。
- 自定义目录用户应选择实际数据库文件。不同来源存在相同供应商 ID 时不会覆盖，需手动核对。

## 接入体检

第一批支持 Claude Code、Codex 的 API Key 供应商及 Anthropic Messages、OpenAI Chat Completions、OpenAI Responses 三种协议。

1. 检查所选供应商与本地配置的地址、凭据是否一致。路由模式下明确标记此项未验证。
2. 默认只查询模型目录，不产生模型文本。
3. 填写模型 ID 并勾选计费提示后，发送普通响应、流式、工具调用及工具结果续接，最多四个请求；每个请求输出上限 128 tokens。
4. 工具测试验证名称、JSON 参数和调用 ID，再回传固定的模拟结果验证下一轮文本响应，不执行任何工具。上一阶段失败或缺少调用 ID 时不继续发送续接请求。

请求使用固定测试内容、全局代理配置和供应商 User-Agent，不读取历史对话。连接超时 10 秒，每项请求最多 45 秒，响应体上限 2 MiB，不携带 Key 跟随 HTTP 重定向，不将原始上游响应或凭据返回到 UI。体检不更新故障转移熔断器。

完整 URL 配置没有可推断的独立模型目录时跳过目录检测。OAuth、Gemini Native 暂不支持本次真实请求体检。HTTP 200 不足以通过：文本响应需符合协议，流式需有文本及结束事件，工具需有指定名称和参数。

通过仅代表本次请求兼容，不保证编程质量、所有 Agent 功能、长任务稳定性或运行中客户端已加载新配置。体检直连所选供应商，不覆盖本地代理的协议转换链路。

## 配置保护

保护开关在本机按 Claude Code/Codex 分开保存，不随数据库恢复同步。为保持已有用户行为，默认关闭，在工作台主动开启。

- Claude：更新 Anthropic 接入环境变量及模型，保留 Hooks、权限、自定义环境变量等本地字段。
- Codex：更新模型、当前供应商定义及相关接入字段；保留其他供应商定义、MCP、其他偏好和 TOML 注释。
- 开启后，供应商直连切换保存原始文件快照；写入失败尝试恢复文件和原供应商选择。
- 工作台安全切换先预览差异，确认时在切换锁内核验本地文件、目录、目标配置和保护状态，变更后必须重新预览。
- 快照包含 Claude settings.json，或 Codex config.toml、auth.json、自动生成的模型目录。显示最近 30 条，保存在本机 HRouter 配置目录的 `switch-snapshots` 子目录中，包含敏感凭据。
- 只有当前文件仍与切换完成时一致、目录不变、原供应商仍存在，才能恢复；不强行覆盖后续编辑。启用代理接管时拒绝直连快照恢复。

### Lite 和同步范围

- Lite 模式强制 Claude / Codex 配置保护、提示词保护、仅供应商同步；跳过通用配置合并和切换时的旧供应商配置回填，停用 MCP、Skills 和提示词的管理写入。已有扩展不会被删除。其他客户端的供应商写入仍沿用原有方式。
- 提示词保护也可独立开启，阻止应用管理的 CLAUDE.md / AGENTS.md 导入、修改和启用操作。
- WebDAV / S3 仅供应商同步可独立开启。快照只传输供应商与端点记录，接收时保留本机其他数据库表及 Skills。Claude / Codex 的供应商内容会过滤非接入字段，其他客户端保留完整供应商条目。
- 所有设备应安装支持此模式的版本并开启开关；使用独立的远端目录或 S3 前缀。旧版客户端不识别仅供应商快照。此选项不追溯删除已经上传的旧快照。
- 上述模式开关保存在本机，不受云端数据库导入覆盖。快照不是完整数据库或会话备份。

### Windows / WSL 独立配置目标

保存环境名称、应用、配置目录绝对路径及供应商。支持 Claude / Codex API Key，目录必须已经存在，WSL 可使用 Windows 能访问的 UNC 路径。先预览实际文件路径，再确认部署；确认时重新核验指纹，文件或供应商改变后必须重新预览。

部署前在本机 `environment-snapshots` 中保存文件和本机供应商选择；写入失败尝试恢复并报告恢复错误。部署到当前本机目录时同步更新当前供应商；已被代理接管的本机目录拒绝部署。远端目录不会改变本机供应商选择。环境快照目前供手动恢复，不能在安全切换的快照列表内一键恢复。

Claude 保留目标 Hooks 和自定义配置。Codex 保留目标 MCP 等配置，使用供应商级认证，不改 auth.json，不复制 Windows 生成的本地模型目录。此功能不自动发现发行版、启动 WSL 或代理服务；WSL 内可访问性仍需实测。

## Codex 模型与会话兼容

- 自定义供应商表单支持同时启用 `features.api_key_model_discovery` 与当前供应商的 `model_catalog_url`，默认使用 Base URL 下的 `/models`。适用于支持此功能的 Codex 客户端；客户端版本和服务端目录格式仍需匹配。本地 `model_catalog_json` 不被删除且可能优先。
- 可按供应商选择 Codex 会话兼容模式。仅修改代理转发中的请求，移除旧上游 response/item 标识和不可跨站复用的 reasoning 内容，保留完整消息与工具调用/结果配对。若仅有旧 response ID 而没有历史消息，或存在 item_reference，则拒绝并提示重新提供上下文。
- 不修改历史 JSONL、会话数据库或官方登录状态；不能从仅保存在旧服务器的上下文恢复会话，也不保证不同模型工具能力一致。

## 主备线路、费用和 HRouter 服务

- 展示真实代理运行状态、当前应用接管状态与活动目标；复用现有故障转移队列和熔断逻辑。
- 用户自行添加供应商并开启路由及故障转移，HRouter 不会被自动加入队列。顺序沿用配置中心供应商排序。
- 自动故障转移启用时，托盘手动切换保留自动模式，将选择设为临时首选，随后仍可尝试备用；选择 Auto 清除临时首选。
- 支持按请求模型精确匹配独立主备链，未匹配时使用原应用线路。模型路由不改变全局当前供应商，尝试次数受现有重试上限约束。每个 Key 可建成独立供应商加入主备链。
- 可按模型线路组手动查询各 Key 已配置的用量接口。需用户确认额度相互独立后才按相同单位合计；共享账户余额不应相加，失败或缺失额度单独标记。
- Anthropic 兼容供应商可显式启用标准 HTTP 传输；默认仍保留原始 Header 大小写路径。修复无 Header 大小写扩展时可能绕过已配置 HTTP 代理的问题，标准 TLS 客户端采用同一根证书配置。原始传输失败不额外隐式重发一次 POST。
- 本地统计不要求登录，明确标注为按配置价格计算的估算值。
- HRouter 登录后显示服务端余额、累计实际消费和服务端逐笔消费入口；余额低于用户阈值时在页面提示，页面打开期间每分钟刷新余额。
- 账单核对由用户选定本地供应商与 HRouter Key，以相同日期和本机时区查询。USD/CNY 默认分别展示；只有用户提供参考汇率才计算参考差额。日期跨度限制 93 天。
- 服务端可能包含其他设备/应用；本地数据可能漏归属、存在重试或估价差异。参考差额不用于认定多扣费。
- HRouter 登录/了解入口为可选，不创建试用额度、订单或扣款。

### 用量修正与历史重建

- Codex fork 统计不再要求父会话在 fork 后还有事件，避免闲置父会话的子会话长期延期导入；继续排除 fork 前继承的用量。
- Claude 统计区分 5 分钟和 1 小时缓存写入，持久化 1 小时用量。1 小时按配置输入价的 2 倍估算，5 分钟按配置缓存写入价估算，再应用供应商倍率。旧记录缺失 TTL 时无法自动还原。
- 用量汇总裁剪时在同一事务登记原始记录 ID，后续重扫不能把已汇总记录再次计费。OpenCode 未完整写入的消息不会阻塞整个源游标；消息后续更新时重新扫描。
- 费用页支持备份后重建 OpenCode 用量，只清理该来源的明细、汇总、去重记录及游标，再从仍在本机的原始日志导入。历史源数据已删除的部分不能重建；不会修改原始 OpenCode 数据库。

## 验证

前端交互测试覆盖免登录通用接入、迁移预览与选择、付费体检确认、预览指纹冲突，以及免登录本地统计。

Rust 测试覆盖严格流式/工具判定与三协议工具续接、迁移不修改源数据库、Lite/同步隔离、Claude 字段保护、Codex TOML/MCP 保留、快照恢复、陈旧预览拒绝写入、多环境部署及本机身份一致性、模型主备链与手动优先级、代理 CONNECT、混合 TTL 计价、Codex fork 和 OpenCode 汇总去重。

真实供应商请求会消耗用户额度，因此自动化验证使用隔离数据；上线前仍需使用测试 Key 在桌面端执行真实链路验收。
