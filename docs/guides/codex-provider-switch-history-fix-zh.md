# Codex 切换供应商时保留当前会话历史

## 问题与修复范围

供应商的 `model_provider` 同时也是 Codex 会话的归类标识。旧的切换路径直接写入目标供应商的标识，例如从 `rightcode` 改为 `private-relay`，可能让原标识下的历史不再出现在当前列表中。这不等同于对话文件被删除。

本次修复把**当前会话标识**与**实际请求供应商**分开：

- 当前 live 配置存在第三方标识时，直接切换和本地路由热切换均沿用该标识。
- 接口地址、供应商显示名称、模型和认证仍随目标供应商更新，不会因为保留旧标识而把请求发回旧供应商。
- 本地路由的恢复备份也保留相同标识，避免关闭路由后历史列表再次变化。
- 匹配当前供应商的 profile 引用同步改写；遇到占用的目标表时交换表和引用，不删除其他供应商配置。
- 回填数据库时还原供应商模板自己的标识，避免把运行时的会话标识永久写入另一个供应商的模板。
- 没有现有第三方标识时保留目标模板的标识；内建供应商标识不强制改写。

**普通切换不修改历史 JSONL 文件，也不修改 Codex 的会话 SQLite 数据库。** 这样不需要在切换时扫描全部历史，也不会与正在追加内容的会话文件发生写入竞争。

## 官方账号与第三方之间的切换

官方与第三方是否合并仍由「设置 → 通用 → Codex 应用增强 → 统一 Codex 会话历史」控制，修复不会偷偷开启这个选项或替用户迁移官方历史。

开启统一后，官方本地路由也使用 `custom` 会话标识，不再绕过这个设置而启用独立标识。专用的旧路由表仅用于识别 HRouter 接管；异常清理时检查表内容匹配，避免误删用户自己的路由。正常关闭路由从备份恢复，异常清理也保留统一会话标识和官方认证语义。

既有的历史迁移/备份/还原功能维持原有显式选择机制。本修复防止后续切换再次隔开**当前可见历史**，不自动合并以前已分散到其他标识下的全部会话，也不恢复已被删除的文件。

## 验证

回归测试覆盖：

- 不同第三方供应商来回切换，标识稳定而请求地址正确变化。
- JSONL 的完整字节和 SQLite 文件在普通切换前后不变。
- OAuth 保留、API key 回填、供应商模板与 profile 还原。
- 本地路由热切换、停止中的路由、路由恢复后的会话标识。
- 官方统一历史路由的生成、接管识别和异常清理。
- inline table、冲突表交换、无效 TOML 和内建供应商边界。

本地命令：

```sh
cargo test --manifest-path src-tauri/Cargo.toml --lib codex_ --no-default-features -- --test-threads=1
cargo test --manifest-path src-tauri/Cargo.toml --test provider_service --no-default-features -- --test-threads=1
```

这些测试使用隔离的临时配置目录，不应以用户正在使用的 Codex 会话目录作为测试数据。

## 补充：对话可见但无法编辑或继续（2026-10-03）

本机复现日志中，`thread/turns/list` 成功，但紧接着的 `thread/resume` 返回：

```text
failed to load configuration: Model provider `cc-switch-official` not found
```

旧的官方代理会话仍携带 `cc-switch-official`。只保留列表的会话标识不够：切换后若删掉这个 provider 表，会话虽能展示，却无法恢复，编辑消息也会失败。先前的 HTTP 502 与这个配置加载错误应分别诊断。

修复在普通供应商写入、代理热切换和备份恢复的最终配置中，补充一个 **live-only 旧标识兼容表**：

- 指向当前选择的 provider，复制最终的端点、认证和协议字段；关闭代理时不保留已经停用的本地端点或占位 token。
- 不改变顶层 `model_provider`，不修改 JSONL / SQLite，不自动开启统一历史设置。
- 使用注释区分兼容表和官方代理接管标记，避免错误触发官方路由清理；重新接管官方路由时仍使用真正的接管标记。
- 回填供应商数据库前移除生成的兼容表，不把旧供应商凭据永久存进新模板。
- 不覆盖显式存在且没有 HRouter 兼容标记的用户自定义同名表。

已受影响的安装需要再次应用修复后的配置。只更新源代码并不会修改正在运行的安装；恢复后重新打开对话验证编辑/继续操作，不用删除对话或迁移消息。
