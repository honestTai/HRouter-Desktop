## 自动化验证

- v0.3.0 发布检查：Rust 单元与集成测试共 2495 项通过，5 项原有忽略；使用隔离测试目录和单线程运行。
- 前端全量 121 个测试文件、792 项通过，使用最多两个 worker；包含工作台语言切换、路由、额度、配置缓存隔离、迁移和模型目录。
- TypeScript 类型检查、renderer 生产构建、前端格式、Rust 格式、Clippy（警告视为错误）及 Git 空白错误检查通过。
- renderer 构建仍提示主包体积超过建议阈值。未用真实 Key 消耗额度验证，未执行真实 WSL / macOS 客户端验收；签名打包不等于这些业务链路已实测。

## 发布前人工验收

1. 在 Windows 桌面端用测试 Key 跑普通、流式、工具及工具续接，再让 Claude Code / Codex 完成一个实际读写文件任务。
2. 开启本地代理，以两家测试供应商验证手动热切换、主站失败后的备用及按模型路由；确认计费没有新增的隐式重发。
3. 使用新旧 Codex 各一版验证模型目录格式及本地目录优先级；跨站续聊分别验证完整历史、仅 response ID、工具调用历史。
4. Windows + 实际 WSL 配置两个目标，核对文件、认证、模型、网络可达及本机当前供应商显示。再验证独立同步目录下两台设备的 Lite / 提示词保护。
5. 对历史用量先备份、记录旧汇总，再用仍存在的源数据库执行 OpenCode 重建，比较可追溯的样本；服务商账单与本地估算分别展示。

## 宣传用语

可描述为：**“面向多供应商的 AI 编程接入工具，提供配置保护、接入体检、按模型主备路由、多环境配置与可追溯用量。”**

当前不宜描述为“全部上游问题彻底修复”“任意旧会话无损续聊”“所有中转站即配即用”或“账单百分之百准确”。这份清单中的兼容性验证范围应随实测结果更新。
